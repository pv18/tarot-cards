# AGENTS.md — tarot-cards

Инструкции для агентов и разработчиков, работающих в этом репозитории.

## Проект

Сайт раскладов Таро. Стек: **React 18 + TypeScript (strict) + Vite +
react-router 6 + Sass (CSS Modules)**. UI — собственный кит
(`src/components/ui`), внешних UI-библиотек нет. Колода — 78 карт, картинки в
`public/img/<id>.jpg`, `id` от 1 до 78.

## Команды

| Команда             | Что делает                                 |
| ------------------- | ------------------------------------------ |
| `yarn dev`          | dev-сервер на http://localhost:5173        |
| `yarn build`        | проверка типов (`tsc`) + прод-сборка       |
| `yarn preview`      | предпросмотр прод-сборки из `dist/`        |
| `yarn lint`         | ESLint (в flat config: `eslint.config.js`) |
| `yarn lint:fix`     | ESLint с автоисправлениями                 |
| `yarn format`       | Prettier по всем файлам                    |
| `yarn format:check` | проверка форматирования без записи         |

**Перед коммитом** должны проходить без ошибок: `yarn build`, `yarn lint`,
`yarn format:check`. Варнинги `react-hooks/exhaustive-deps` и
`react-refresh/only-export-components` — не игнорировать: разбираться или
задокументировать причину.

## Структура

```
src/
  components/<Name>/  переиспользуемые компоненты: <Name>.tsx + <Name>.module.scss
  components/ui/      собственный UI-кит: Button, TextInput, Chip, Modal,
                      Segmented, Switch, Popconfirm, Spinner, EmptyState
  pages/<Name>/       страницы; маршруты объявляются в src/routes/index.ts
  data/               статические данные колоды (карты, толкования)
  utils/              чистые функции без побочных эффектов (тасовка, тяга карт)
  types/              общие типы и интерфейсы
  styles/             глобальные стили и тема (фон, шрифты, палитра)
```

Новые сущности кладутся в существующие папки по этому образцу; не создавать
«свалки» вроде `src/helpers/`, `src/common/`.

## Чистый код в React — обязательные практики

- **Компоненты** — только функциональные (стрелочные `React.FC`). Классовых
  компонентов, `ReactDOM.render`, наследования — не допускать.
- **Один компонент — один файл**, имя файла совпадает с именем компонента
  (PascalCase). Файл страниц: `src/pages/<Name>/<Name>.tsx`.
- **Хуки** — только на верхнем уровне компонента. Логику, которую переиспользуют
  два+ компонента, выносить в кастомный хук (`src/hooks/<useName>.ts`);
  чистые вычисления — в `src/utils/`.
- **Иммутабельность state**: не мутировать массивы и объекты в `setState`
  (никаких `push`, `sort` на месте). Для тасовки использовать `shuffle` из
  `src/utils/deck.ts`, для новых массивов — spread.
- **Ключи списков** — стабильные `id` из данных. Никогда не использовать
  `uuid()`, `v1()`, `Math.random()` или индекс массива в качестве ключа. Если
  стабильного `id` нет — добавить его в данные.
- **Типизация**: `strict` включён. Не допускать `any` и `@ts-ignore`. Типы
  общих сущностей экспортировать из `src/types/types.ts`; пропсы компонента —
  именованным интерфейсом. Импортировать типы через `import type`.
- **Состояние**: `useState` для простых значений; производные данные вычислять
  в рендере или через `useMemo` — не дублировать в state.
- **Стили**: только CSS Modules (`*.module.scss`). Глобальные стили — тема и
  фон в `src/styles/global.scss`. **Все цвета интерфейса читаются только из
  `:root`-токенов** `global.scss` (`--accent`, `--text`, `--surface`…);
  хардкод цветов в module.scss запрещён, полупрозрачные варианты — через
  `color-mix(in srgb, var(--token) N%, transparent)`. Тёмные темы — блоки
  `[data-theme='…']` с полным набором токенов; новая тема = новый блок +
  запись в `THEMES` в `src/utils/theme.ts` и `src/components/MenuPanel`.
  SCSS-переменные в module.scss не импортируются — общие значения кита
  записываются значением, канон — в `global.scss`.
- **UI-кит** (`src/components/ui`): кнопки, поля, теги, модалки и подтверждения
  — только из кита, никаких внешних UI-библиотек. Варианты кнопок:
  `primary` / `ghost` / `danger`. Модалка сама закрывается по Escape и клику по
  фону.
- **Форматирование** — зона ответственности Prettier (`.prettierrc.json`),
  линт — ESLint (`eslint.config.js`). Не «править» форматтер руками.
- **Комментарии** — по делу, объясняют «почему», а не «что». Не оставлять
  закомментированный код и `console.log` в main-ветке.

## Данные колоды

- Единственный источник истины — `src/data/cards.ts` (собирает `majorArcana.ts`
  и `minorArcana.ts`). `id` карты = имя файла картинки.
- Названия и порядок соответствуют колоде на картинках (1 = Шут, 23 = Туз
  Кубков, 37 = Туз Мечей, 51 = Туз Пентаклей, 65 = Туз Посохов). Не менять
  произвольно: расхождение ломает соответствие «данные ↔ картинка».
- Правки толкований — отдельным коммитом с понятным сообщением.

## Git

### Формат коммитов

`<type>: <описание на русском>` — тип латиницей, описание кириллицей, коротко и
по сути. Исторические коммиты в старом формате не переписывать.

Типы:

| Тип        | Когда использовать                        |
| ---------- | ----------------------------------------- |
| `feat`     | новая функциональность                    |
| `fix`      | исправление бага                          |
| `refactor` | изменение кода без изменения поведения    |
| `style`    | только визуал/вёрстка, без логики         |
| `docs`     | документация (README, AGENTS.md, ROADMAP) |
| `chore`    | туллинг, зависимости, конфиги             |
| `perf`     | оптимизация производительности            |
| `test`     | тесты                                     |

Примеры:

```
feat: страница «Три карты» с выбором вопроса
fix: тасовка больше не мутирует исходную колоду
chore: настроен husky и commitlint
docs: добавлен раздел про расклады в AGENTS.md
style: увеличены отступы на странице «Все карты»
```

- При необходимости уточнить область — scope после типа:
  `feat(cards): …`, `fix(deck): …`.
- Тело коммита (пустая строка, затем пояснение) — опционально, для нетривиальных
  изменений: «что и почему», не пересказ диффа.
- Один коммит — одна цель: миграция, фича или правка туллинга не смешиваются.
- `dist/` и `node_modules/` не коммитятся (в `.gitignore`).
- Пушить только по явной просьбе пользователя.
